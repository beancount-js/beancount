# Design-system renderer audit

This audit records the visual source that has been copied into
`@beancount-js/ui` before any application import is changed. A UI component
accepts display-ready models and callbacks; it must not read a Fava store,
route, server API, ledger object, or formatter context.

## Fava application adapters intentionally retained

These Fava components remain application boundaries rather than cross-app UI
primitives. They must not move Fava routes, stores, server APIs, formatter
context, or ledger-derived state into `@beancount-js/ui`. Extract a visual only
after it accepts a complete display-ready model and callbacks.

- Chart rendering: `ChartPanel` plus the UI-owned `LineChart`, `ScatterPlot`,
  `BarChart`, `HierarchyChart`, `FinancialDashboard`, `DashboardDonut`,
  `DashboardLine`, `DashboardFlow`, and `DashboardTreeTable` accept display
  models. Fava's `Chart` adapter remains responsible for data selection,
  formatting, conversion, interval, and routes until consumer migration.
- Review and import surfaces: `ImportTable`. The UI-owned
  `IngestionReviewTable` covers grouped queue presentation, selection, and row
  callbacks, while `ImportMappingTable` covers controlled account mapping. Fava
  still applies parsing, matching, source rewrites, upload, persistence, search,
  pagination, review sheets, and mutation APIs. `AccountBulkActionSheet`'s Fava
  adapter still owns patch calculation, confirmation, and saves.
- Workspace adapters: `StudioWorkspaceShell`, `AppShell`,
  `StudioShellHeader`, `WorkspaceTreeNavigation`, and
  `LedgerWorkspaceNavigation` are UI-owned. Fava's `StudioShell` and
  `FavaNavigation` retain project selection, ledger/tag filtering, route
  selection, local storage, responsive sidebar state, picker data, and server
  actions until consumer migration.
- Domain adapters: Fava's `JournalTable` composes the UI-owned
  `LedgerActivityTable` and `AccountBulkActionSheet`; it retains ledger data,
  balance derivation, workspace-header wiring, patches, and saves. `QueryTable`,
  reconciliation flows, and dashboard containers retain their Fava data,
  ranking, Brand Match, and persistence adapters until consumer migration.
- Editor adapters: `Editor`, `EditorDialog`, and `ImportEditor` retain
  Beancount/BQL language setup, file synchronisation, source positions, command
  dispatch, linting, formatting, and save actions. The shared `CodeEditor`,
  `CodeHighlighter`, and syntax-token palette are their UI foundation; Fava
  supplies the relevant language parser and must not import Fava CodeMirror
  extensions into `@beancount-js/ui`.
- Search and account adapters: `Search`, `AccountDetails`, `AccountActivityTable`,
  `AccountTable`, `Query`, and report routes retain ledger filtering, BQL,
  account-tree derivation, interval selection, and route state. They compose
  the UI search controls, account link, charts, and table display models.
- AI and ingestion adapters: `AiDock`, the journal and ingestion sheets,
  merchant review, source configuration, and reconciliation panels retain
  session/API streams, approval decisions, file mutations, matching,
  persistence, and project-local state. `ReviewDiff` is the provider-agnostic
  visual extracted from `AiUnifiedReviewDiff`; never copy API or mutation logic
  into the UI package.

## Completion rule for a copied visual surface

1. Add the prop-driven component, styles, Docs description, and interaction
   stories in `packages/ui/src/components`.
2. Cover error, empty, and meaningful interactive states in the component's
   Storybook tests and pass the catalog accessibility gate.
3. Remove only that component's direct Fava story from
   `.storybook/main.ts`; do not modify or delete the production Fava source.
4. Run `pnpm --filter @beancount-js/ui checks` and commit the copy before
   starting another surface.
5. Migrate Fava imports only after the visual model is manually approved. The
   adapter may then become a small data/route boundary rather than another
   component implementation.
6. Keep UI source and build configuration independent from Fava. The package
   boundary check must pass without Fava aliases, scans, source imports, or
   application-only SvelteKit aliases.
